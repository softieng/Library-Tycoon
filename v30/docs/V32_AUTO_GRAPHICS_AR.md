# Library Tycoon V3.2 | الضبط التلقائي لجودة الرسوميات

## الهدف
اختيار جودة أولية مناسبة لقدرات متصفح اللاعب، ثم تعديل الجودة ودقة العرض تدريجياً على أساس متوسط معدل الإطارات الحقيقي (FPS). لا يقرأ المتصفح رقم بطاقة الرسوميات أو سعة VRAM دائماً. بعض المتصفحات تخفي اسم GPU أو مقدار RAM. لذلك لا تُقدَّم هذه الميزة على أنها فحص كامل لمواصفات Windows.

## الأجهزة المستهدفة
- الحاسبة الرئيسة: Intel Core i7-12700H، بطاقة RTX 3070 Ti Laptop 8GB، وRAM نحو 16GB. إذا أظهر WebGL البطاقة المنفصلة وتعّرف المتصفح على مؤشرات الذاكرة والأنوية، يبدأ من `high / 1.0`. إن أخفى المتصفح البيانات يبدأ من `medium` ويرتفع عند استقرار FPS.
- جهاز منخفض المواصفات مثل Dell N5040 بذاكرة 2GB: `low / 0.70` عند ظهور مؤشرات الجهاز الضعيف. إذا استعمل المتصفح رسام SwiftShader البرمجي، يبدأ من `low / 0.55`.
- أجهزة ببطاقة مدمجة أو بيانات مخفية: `medium / 0.85` في العادة، ثم تُقاس السرعة لتعديل المستوى.

هذه قواعد بدء، وليست وعداً بمعدل إطارات معين على أي جهاز.

## طريقة العمل
1. `browserHardwareHints()` يقرأ مؤشرات تقريبية ومتاحـة للمتصفح فقط: عدد الأنوية المنطقية، مؤشر ذاكرة محدود إن توفر، اسم WebGL renderer إن أتاحه المتصفح، أبعاد النافذة، ومؤشر شاشة لمس.
2. `recommendedAutoProfile()` يختار أول جودة: low أو medium أو high. لا تتغير موديلات الشخصيات أو أصول الشعارات.
3. `AutoQualitySampler` يراقب FPS على نافذة مرئية بعد فترة استقرار، ويهمل قياسات التبويب المخفي.
4. الجودة تنخفض عند متوسط أقل من 40 FPS لمدة كافية، وترتفع عند متوسط أعلى من 59 FPS لفترة أطول، وبحد أدنى 20 ثانية بين القرارات. أي تعديل يتم بخطوة واحدة لتقليل تذبذب الجودة.
5. في وضع `low` ينخفض renderScale تدريجياً إلى 0.55 كحد أدنى. في وضع `high` يرجع إلى 1.0 إذا سمح الأداء.
6. اختيار اللاعب أي مستوى أو تغيير شريط دقة العرض يعطّل الوضع التلقائي. خيار `ضبط الجودة تلقائياً` يعيده.
7. الإعدادات منفصلة عن حفظ المهمة/الرصيد. وتُحترم إعدادات الجودة اليدوية القديمة عند تحديث اللعبة.

## ضوابط السلامة
- لا رفع لمعلومات العتاد إلى خادم، ولا تعديل بيانات Koha أو قواعد المكتبة.
- لا تغيير على اقتصاد اللعبة، أو نظام الموظفين، أو معرفات الرفوف، أو المهام، أو ملفات الهوية والشعارات.
- لا تعديل لنسخ GitHub Pages المنشورة أو `main`. التغيير في فرع مراجعة منفصل.
- `FLAGS.multiHall=false` يبقى كما هو، فلا ادعاء بإكمال القاعات الخمس الأخرى.
- انخفاض جودة العرض لا يقلل جودة منطق اللعب أو عدد الزوار، ويشمل فقط الإضاءة والظل والمؤثرات ودقة العرض.

## فحص القبول
من داخل `v30/`: `npm ci` ثم `npm run typecheck` ثم `npm test` ثم `npm run assets:verify` ثم `npm run build`.

في متصفح Chrome أو Edge على Windows: فعّل الإعدادات ثم شغّل قاعة الخوارزمي دقيقة كاملة مع زوار، وراقب FPS، اختبر اختيار جودة يدوية وإعادة التحميل، ثم أعد الوضع التلقائي. احفظ حالة اللعبة، وأعد تحميلها، وتحقق من الرصيد والمهمات والموظفين. اختبر كذلك متصفحاً ضعيفاً مع تصيير برمجي إن توفر، ولا تفسر نتائج SwiftShader على أنها أداء البطاقة الرسومية الحقيقية.

## مستوى القبول
هذا تحديث مصدر قابل للاختبار. لا يمكن الجزم بتحقيق 60FPS على RTX 3070 Ti أو 30FPS على Dell N5040 دون تجربة على الأجهزة نفسها.
